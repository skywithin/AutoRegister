## Context

Registration relies on runtime reflection: `Assembly.GetTypes()`, then `AddScoped(Type, Type)`. That has three consequences:

- **No trimming or Native AOT.** Reflection over all types is exactly what trimming and Native AOT break.
- **Late errors.** Configuration mistakes only surface at startup, in the console or (after BL-0005) as an exception, never at compile time.
- **Startup cost.** Each scanned assembly costs reflection time at startup.

An incremental Roslyn source generator could emit a registration method per assembly at compile time. It could report attribute misuse as compiler diagnostics, and it needs no reflection at run time.

## Scope

- Prototype an incremental generator that finds `[AutoRegister]` classes in the compiling project and emits an `Add<Assembly>AutoRegistered(this IServiceCollection)` extension method.
- Map each validation rule to a diagnostic (error or warning ID).
- Measure startup time against the reflection path on a sample with a few hundred services.
- Check behaviour for `internal` types, nested types and partial classes, and AOT and trimming compatibility (publish a Native AOT sample).
- Write up a recommendation:
  - generator only, both side by side, or don't pursue;
  - what it means for the public API and package layout (an analyzer/generator package alongside the runtime one);
  - versioning.

## Acceptance criteria

- [ ] A written recommendation in this item with the measurements and a go/no-go decision.

## Locations

## Decision points

- Whether AOT support is a goal for this library's users at all. If not, the main remaining benefit is compile-time diagnostics, which an analyzer alone could provide.
