## Context

`AddAutoRegisteredServicesFromAssembly(params Assembly[])` is the only entry point and takes no configuration. Logging can't be switched off or redirected, duplicate registrations can't be avoided, types can't be filtered, and the failure mode can't be chosen. Because `params` must be the last parameter, every new option would need another overload. Several other items (logging, fail-fast, duplicate handling) need a place to be configured, and this entry point is that place.

## Scope

- Add an `AutoRegisterOptions` type and an entry point that takes it, for example `services.AddAutoRegistered(o => o.FromAssemblies(a, b))`.
- Start with only the assembly list. Later items add their own options (logger, failure mode, duplicate handling).
- Keep `AddAutoRegisteredServicesFromAssembly(params Assembly[])` with unchanged behaviour, implemented on top of the new entry point.
- Move the scan and registration logic so both entry points share it.

## Acceptance criteria

- [ ] The new entry point registers exactly what the existing method registers for the same assemblies; a test asserts identical descriptors.
- [ ] The existing method's behaviour and tests are unchanged.
- [ ] Options are validated: no assemblies or a `null` assembly throws `ArgumentException`.
- [ ] `dotnet build` and the full test suite pass.
- [ ] README and `docs/` (Getting-Started, API-Reference) updated.

## Locations

- `src/AutoRegister.DI/IoCExtensions.cs`, a new options file
- `tests/AutoRegister.DI.Tests/`
- `README.md`, `docs/Getting-Started.md`, `docs/API-Reference.md`

## Decision points

- Method name: `AddAutoRegistered`, `AddAutoRegisteredServices` or another name. It must not clash with the existing method's overloads.
- Builder-style API (`o.FromAssemblies(...)`) or plain settable properties.
- Whether to mark the old method `[Obsolete]` now, or only in the next major version.
