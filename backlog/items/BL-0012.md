## Context

The example exists to show the layered registration pattern: `AssemblyReference` per project, chained `AddDemoX()` bootstrap methods, and `[AutoRegister]` classes spread across layers. Most of its code has nothing to do with that:

- `UserService` has seven CRUD and search methods with `Task.Delay`, logging and email-uniqueness validation.
- The DTOs and the `User` model carry data-annotation attributes that nothing validates.
- `IUserService` has an XML doc on every member.

Readers have to wade through this to find the four or five classes that matter.

## Scope

- Keep all five layers, one `[AutoRegister]` service per layer, the `AssemblyReference` and bootstrap pattern, and the lifetime demo in `Demo.ConsoleApp`.
- Cut `IUserService` and `UserService` down to create and get-by-ID (plus list, if the scenario output needs it). Remove the update, delete, search and get-by-email paths and the simulated delays.
- Reduce the DTOs and `User` to the fields the scenario prints; drop the data annotations.
- Shrink `IUserDataProvider` to match.
- Keep the console output readable and keep `docs/Examples.md` in sync.

## Acceptance criteria

- [x] `dotnet run --project example/Demo.ConsoleApp` still shows the registration log, the lifetime comparison and the cross-scope user scenario.
- [x] Every remaining class either carries `[AutoRegister]`, is a bootstrap or `AssemblyReference` file, or is needed by the scenario.
- [x] `dotnet build AutoRegister.slnx` succeeds with no warnings, and the full test suite passes.
- [x] `docs/Examples.md` snippets match the trimmed code.

- Whether `Demo.Domain` should get an `[AutoRegister]` class of its own, so every layer visibly registers something. Today it only defines abstractions and its scan registers nothing.

## Resolution (2026-10-27)

- `User` is now a four-field record (`Id`, `Name`, `Email`, `CreatedAt`); the `Dtos/` folder, data annotations and XML docs are gone.
- `IUserDataProvider` has only `Add` and `Find`; `UserDataProvider` is still a `ConcurrentDictionary`-backed singleton, without seed data.
- `IUserService` has synchronous `Create` and `GetById`. `UserService` keeps its two cross-layer dependencies (`IUserDataProvider`, `IClockService`) and drops the logger, delays and validation, so `Demo.Application` no longer references `Microsoft.Extensions.Logging.Abstractions`.
- `UserScenario` creates in one scope and gets by ID in another; `Program.cs` no longer needs the log-level override.
- `docs/Examples.md` shows the trimmed code.
- Decision point: `Demo.Domain` gets no `[AutoRegister]` class. Its empty scan already shows that every layer scans its own assembly, and `docs/Examples.md` explains it; a made-up domain service would be filler.

No library change; no version impact.
