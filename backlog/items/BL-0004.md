## Context

`ConsoleHelper` writes every scan, registration, warning and error to standard output and changes `Console.ForegroundColor` around each line. A library shouldn't have that side effect:

- It pollutes structured logs and test output.
- It can't be turned off or redirected.
- Changing the global console colour isn't thread-safe.
- In hosted environments, warnings about skipped registrations often end up where nobody sees them.

## Scope

- Add a logging option to `AutoRegisterOptions`, either an `ILogger` or an `Action<AutoRegisterLogEntry>` callback with a level, message and type.
- Default for the new entry point: no output.
- The old `AddAutoRegisteredServicesFromAssembly` gets a documented decision: keep console output for compatibility, or go silent in the major version.
- Delete `ConsoleHelper`, or keep it only as an opt-in console sink that doesn't change the console colour.
- Keep the same messages and levels: info for scan and registration, warning, error.

## Acceptance criteria

- [ ] With no logger configured, the new entry point writes nothing to `Console`; a test captures `Console.Out` to check this.
- [ ] A configured logger receives every scan, registration, warning and error, at the right level.
- [ ] `Console.ForegroundColor` is never changed.
- [ ] `dotnet build` and the full test suite pass.
- [ ] README and `docs/` updated: the API-Reference "Console output" section and Troubleshooting.

## Locations

- `src/AutoRegister.DI/ConsoleHelper.cs`, `src/AutoRegister.DI/IoCExtensions.cs`
- `docs/API-Reference.md`, `docs/Troubleshooting.md`, `README.md`

## Decision points

- `ILogger` (requires `Microsoft.Extensions.Logging.Abstractions` as a new dependency) or a callback (no new dependency; callers adapt it to `ILogger`). The library has only one dependency today, which favours the callback.
- What the legacy entry point does by default.
