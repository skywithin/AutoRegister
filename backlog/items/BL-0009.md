## Context

The attribute's shape makes it hard to extend and has a few loose ends:

- The optional interface is a constructor argument, so every new option needs another constructor overload. Named properties can grow without that.
- `Lifetime` duplicates `Microsoft.Extensions.DependencyInjection.ServiceLifetime` with a different value order (Microsoft: Singleton=0, Scoped=1, Transient=2; here: Scoped=0, Transient=1, Singleton=2).
- `RegisterAs` is a `[Flags]` enum with no named `None` value, yet `0` is a value the code has to handle.
- The attribute class isn't `sealed`.
- `[AttributeUsage]` leaves `Inherited` at its default of `true`, while the scan only honours attributes declared directly on the class.
- The XML doc on `ServiceInterface` says "the first interface implemented by the class will be used", which ignores the filtering rules.

## Scope

- Move optional settings to named properties, for example `[AutoRegister(Lifetime.Scoped, As = typeof(IFoo))]`.
- `sealed` the attribute and set `Inherited = false` and `AllowMultiple = false` explicitly.
- Decide whether to use `ServiceLifetime` directly or keep `Lifetime` (if kept, document why).
- Add `RegisterAs.None = 0` or make `0` impossible to express.
- Fix the XML docs; ship them via `GenerateDocumentationFile` (packaging follow-up).

## Acceptance criteria

- [ ] The attribute is `sealed`, and its `AttributeUsage` matches the scan's behaviour.
- [ ] Optional settings are named properties; the README and docs examples use them.
- [ ] XML docs on every public member are accurate.
- [ ] `dotnet build` and the full test suite pass.
- [ ] README and `docs/` updated, including a migration note for the major version.

## Decision points

- `Lifetime` versus `ServiceLifetime`. Using the Microsoft type removes duplication, but every usage must then add `using Microsoft.Extensions.DependencyInjection;`.
- Whether to keep the three-argument constructor as `[Obsolete]` for one major version.
