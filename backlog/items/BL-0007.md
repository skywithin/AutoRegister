## Context

`RegisterAs.Interface | RegisterAs.Self` creates two independent registrations, so a `Singleton` or `Scoped` class gets one instance when resolved as the class and a different one when resolved through the interface. This is rarely what people expect. For singletons it means duplicated state, and it is currently documented as a pitfall with a manual workaround.

## Scope

- When both flags are set, register the class once with its lifetime. Register each interface with a factory that resolves the class: `sp => sp.GetRequiredService<TImpl>()`.
- `Transient` keeps producing a new instance per resolve; forwarding doesn't change that.
- If only `RegisterAs.Interface` is set, keep registering the interface directly; there is no self registration to share.

## Acceptance criteria

- [ ] For `Singleton` and `Scoped` with `Interface | Self`, resolving the class and the interface in the same scope returns the same instance.
- [ ] `Transient` behaviour is unchanged.
- [ ] Disposal happens once per instance; a test with an `IDisposable` singleton checks this.
- [ ] `dotnet build` and the full test suite pass.
- [ ] README and `docs/` updated: API-Reference `RegisterAs` table, Best-Practices, Troubleshooting, Examples.
