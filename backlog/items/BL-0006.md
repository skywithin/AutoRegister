## Context

Registrations use `Add*`, and nothing records which assemblies were already scanned. Scanning an assembly twice registers every service twice. It's easy to do by accident:

- the same assembly listed twice in one call;
- two entry points chaining the same lower layer's bootstrap method (the documented `AddDemoX()` pattern), for example a web host and a background worker composed in one process.

Duplicates change `IEnumerable<T>` results, and for singletons they create extra instances.

## Scope

- Ignore duplicate assemblies within a single call.
- Remember scanned assemblies on the `IServiceCollection` across calls, for example through a marker singleton holding the set, and skip a rescan.
- Optionally offer `TryAdd` semantics as an option on the new entry point, so a manual registration made earlier is not overridden.

## Acceptance criteria

- [ ] Passing the same assembly twice in one call registers each service once.
- [ ] Two calls with the same assembly on the same `IServiceCollection` register each service once.
- [ ] Separate `ServiceCollection` instances don't share state.
- [ ] `dotnet build` and the full test suite pass.
- [ ] `docs/` updated: API-Reference "Other rules", Troubleshooting "registered twice", Best-Practices and Examples.

## Decision points

- Where to keep the scanned-assembly set: a marker `ServiceDescriptor` (visible in the collection) or a `ConditionalWeakTable<IServiceCollection, ...>` (invisible, but tied to the collection's object identity).
- Whether `TryAdd` is a separate option or the new default.
