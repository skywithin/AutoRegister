## Context

A class can be registered under only one interface. Registering a class under several interfaces is common, for example a store implementing `IReader` and `IWriter`, or a handler implementing several message interfaces. Today it needs manual registration, which defeats the point of the attribute.

## Scope

- Accept several interfaces on the attribute, for example `As = new[] { typeof(IReader), typeof(IWriter) }` or a `params Type[]` constructor, depending on the BL-0009 design.
- Validate each interface the same way a single explicit interface is validated today.
- Register the class once and forward each interface to it, so all interfaces share one instance for `Scoped` and `Singleton` (the same mechanism as BL-0007).

## Acceptance criteria

- [ ] A class can be registered under two or more interfaces, and each resolves.
- [ ] For `Singleton` and `Scoped`, all interfaces resolve to the same instance within a scope.
- [ ] An interface that is not implemented, or a non-interface type, in the list is reported like a single invalid `serviceInterface` is today.
- [ ] `dotnet build` and the full test suite pass.
- [ ] README and `docs/` updated (API-Reference, Examples).
