## Context

Every test scans `Assembly.GetExecutingAssembly()`. The two multi-assembly tests add `System.Private.CoreLib`, which contains no `[AutoRegister]` types, so they only show that scanning it doesn't break anything. Several behaviours are covered only implicitly, by the example building and running, and nothing asserts them:

- **Classes in another assembly**, including `internal` ones, are registered.
- **Interfaces across assemblies:** a class in one assembly implementing an interface from another resolves through that interface.
- **Chained scans:** the bootstrap pattern (a lower layer's scan, then the current one) registers each layer's services exactly once.
- **Scoping:** only the assemblies passed in are scanned, and types in an unscanned referenced assembly are not registered.

## Scope

- Add two small fixture class libraries under `tests/`, for example `AutoRegister.DI.Tests.FixtureA` and `AutoRegister.DI.Tests.FixtureB`, where B references A. Give them:
  - an `internal` class implementing a public interface from the other assembly;
  - a `Self` class;
  - an `AssemblyReference`.
- Reference both from the test project and add them to `AutoRegister.slnx`.
- Put the new tests in their own test class, so fixture types don't change registration counts in `IoCExtensionsTests`.
- Cover:
  - scanning A only;
  - scanning B only, where A's types must not appear;
  - scanning both in one call;
  - chained calls, A then B.

- [x] The existing tests and their registration counts are unchanged.

## Resolution (2026-10-27)

- Added `tests/AutoRegister.DI.Tests.FixtureA` and `FixtureB` (B references A). They contain:
  - an internal class registered under its own public interface;
  - a `Self` class;
  - an interface in A implemented by an internal class in B;
  - a B service whose constructor depends on A's interface;
  - an `AssemblyReference` and an `AddFixtureX()` bootstrap method per fixture, with B chaining A.
- Added `CrossAssemblyRegistrationTests` with four tests:
  - scan A only;
  - scan B only, where nothing from referenced A is registered;
  - scan both in one call, which resolves the cross-assembly dependency;
  - chained bootstrap methods, which register each service type exactly once.
- Decision point: the fixtures set `IsTestProject=false` in their own csproj rather than changing `tests/Directory.Build.props`. They reference no test packages, and `dotnet test AutoRegister.slnx` runs only the real test assembly.
- `IoCExtensionsTests` and its counts are unchanged, because it scans only the executing assembly.
- `CLAUDE.md` Layout describes the fixture projects.

No library change; no version impact. Suite: 34 tests (30 before).
